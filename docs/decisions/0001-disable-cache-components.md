# ADR 0001 — Вимкнути Cache Components і Partial Prefetching (TD-9)

- Статус: прийнято
- Дата: 2026-11-26 (roadmap, день 3)
- Пов'язано: [TECHNICAL_PLAN.md](../TECHNICAL_PLAN.md) §4, §5, §15, §18 (TD-9)

## Контекст

Шаблон `create-next-app` 16.4 увімкнув у `next.config.ts` `cacheComponents: true` і `partialPrefetching: true`. У цьому режимі Next.js будує для кожного маршруту статичну «оболонку», а будь-яке читання даних під час запиту (Prisma, `cookies()`, сесія) має бути:

- або обгорнуте в `<Suspense>` (інакше збірка чи dev-оверлей повідомляють про «blocking route»);
- або закешоване директивою `"use cache"` / `"use cache: private"` з `cacheLife` і `cacheTag`, а мутації мають інвалідувати теги (`updateTag` / `revalidateTag`).

LifeHub — застосунок для одного користувача, усі сторінки (крім `/login`) за входом, і майже кожна читає свіжі дані з PostgreSQL (баланси, бюджети, меню). Статичної частини, яку вигідно віддавати з кешу, майже немає, а похідні показники за §6 не кешуються.

## Рішення

Вимкнути обидві опції (прибрати їх із `next.config.ts`) і працювати з класичною моделлю App Router:

- сторінки, що читають сесію (`cookies()`) або БД, рендеряться динамічно на кожен запит;
- Server Components читають дані через сервіси модулів напряму, без `"use cache"`;
- після мутацій Server Actions викликають `revalidatePath` (TECHNICAL_PLAN §4); `revalidateTag(tag, "max")` має сенс лише тоді, коли з'явиться кеш із тегами (§15);
- `<Suspense>` і `loading.tsx` — за бажанням для UX (наприклад, віджети Dashboard, §15), а не як обов'язкова вимога збірки.

## Наслідки

- **Плюси:** простіша модель для 112 щоденних задач; дані завжди свіжі; Auth.js (день 5) працює без `"use cache: private"`; менше ризику показати застарілий баланс.
- **Мінуси:** немає миттєвої статичної оболонки й часткового префетчу під час навігації; кожен перехід чекає на сервер. Для одного користувача з невеликим обсягом даних це прийнятно.
- **Пильність:** сторінка без динамічних API (`cookies()`, `headers()`, `connection()`) може бути пререндерена статично під час `build`. Після дня 5 усі сторінки читають сесію й тому динамічні; до того сторінка, що читає БД без сесії, має викликати `await connection()` з `next/server`.
- **Повернення:** якщо навігація стане відчутно повільною, Cache Components можна увімкнути пізніше за офіційним гайдом `migrating-to-cache-components` новим ADR.
